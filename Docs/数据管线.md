# 数据管线

策划改的是 CSV，程序读的是 ScriptableObject，中间由导入管线单向搬运并做校验。
**改数值只改表，不改代码、不重编译。**

```
Data/Tables/*.csv  （17 张表 · 入库）
      │  CsvImporter：解析 → 特性列映射 → 校验 → 生成/就地更新资产
      ▼
Data/Definitions/<类型>/<id>.asset    +    Data/Generated/DefinitionCatalog.asset
                                           Data/Generated/ImportManifest.asset（增量依据）

Localization/Tables/localization-zh-Hans.csv
      │  LocalizationImporter
      ▼
Localization/Generated/LocalizationTable_zh-Hans.asset + LocalizationKeys.g.cs
```

## 解析规则（`Data/Runtime/Csv.cs`）

- RFC4180 子集：`"` 包裹字段、字段内逗号与换行、`""` 转义双引号；兼容 UTF-8 with BOM；`#` 开头的行是注释（策划写口径说明用）
- 出错抛 `CsvFormatException(message, lineNumber)`，行号直接指向问题行
- 精确制表符/空行容错：空行忽略，空单元格按「未填写」处理

## 列映射（`Data/Runtime/CsvDefinitionMapper.cs`）

- 列名 → 字段用特性声明：`[CsvColumn("maxHealth", required: true)] private int _maxHealth;`，特性只作用于字段、每字段一个
- `Map(type, row, table, report)` 新建资产；`Apply(definition, row, table, report)` **就地更新**——保留原有 GUID，因此场景与目录资产里的引用不会断
- 规则：空单元格 → 字段回到默认值；引用类型（Sprite/Prefab 等）不可来自 CSV，只能由人在编辑器里指定
- 错误码：`CSV_COLUMN_MISSING`（表头缺列）、`CSV_COLUMN_ABSENT`（行内缺列）、`CSV_VALUE_EMPTY`（必填为空）、`CSV_VALUE_INVALID`（格式/取值非法）、`CSV_COLUMN_UNMAPPED`（表头有列但类型无字段）

## 增量导入（`Editor/Tools/CsvImporter.cs` + `DataImportManifest.cs`）

- 哈希：`CsvTable.ComputeHash()` = FNV1a（表名 + 表头 + 每行内容），表一改哈希就变
- 清单：`Data/Generated/ImportManifest.asset`，每条 `Entry { _tableName, _contentHash, _importedAtUtc, _assetPaths }`
- **跳过的条件**（三个同时成立才跳）：`force == false` 且哈希与清单一致 且 清单记录的资产**仍然存在**（`AssetsStillExist`）
- 清单只在**真的导入过表**时才 `SetDirty` + 落盘（ADR-012），所以重复跑初始化不会留下假改动
- 强制全量：`CsvImporter.ImportAll(force: true)`（改过导入逻辑或怀疑清单不同步时用）

## 校验与唯一性

- 通用校验码（`DefinitionBase.Validate`）：`DEF_ID_EMPTY` / `DEF_ID_PATTERN` / `DEF_LOC_KEY_EMPTY` / `DEF_LOC_KEY_HAS_CHINESE` / `DEF_LOC_KEY_FORMAT` / `DEF_VERSION_INVALID` / `DEF_ICON_MISSING`(Info) / `DEF_TAG_EMPTY` / `DEF_TAG_DUPLICATE`
- 唯一性：`DefinitionCatalog.Rebuild()` 建 ID 索引，重复 ID 报 `DEF_ID_DUPLICATE`；`TryGet / TryGet<T> / Get<T> / OfKind<T>` 供运行期查表
- ID 规则集中在 `Data/Runtime/Ids.cs`（按 `DefinitionKind` 查正则），与既有剧本命名对齐：
  `CHR_*`、`SKL_*`、`STS_*`、`ENM_*`、`ENC|EENC|BENC_CH\d{2}_\d{3}`、`BSP_CH\d{2}_\d{3}_P\d`、`CH\d{2}_MAP\d{2}`、`INT_CH\d{2}_*`、`LUT_/SHP_/RCP_/END_*`
- 剧情节点 ID 另有 `IsValidNarrativeNodeId`（`CH\d\d_N\d{2,3}_*`），状态键 `IsValidStateKey`，本地化键 `IsValidLocalizationKey`；`ContainsChinese` 用于拦截「本地化 key 里塞中文」

## 本地化管线（`Editor/Tools/LocalizationImporter.cs`）

- 输入 `Localization/Tables/localization-zh-Hans.csv` → 表资产 `LocalizationTable_zh-Hans.asset` + 常量类 `LocalizationKeys.g.cs`（常量名走 `IdRules.ToConstantName`）
- 缺键策略：运行期 `Get` 返回 `[[key]]` 并告警，**不回退中文**
- 硬编码中文兜底：`HardcodedChineseScanner`，白名单 `Localization/scan-ignore.txt`（支持 `路径:关键词` 与 `前缀*`）

## 常用操作

| 想做的事 | 怎么做 |
|---|---|
| 改数值 | 改 `Data/Tables/*.csv` → 菜单 `SamsaraWest/数据/数据工具窗口`（Ctrl+Shift+D）导入；或跑 `HeadlessTasks.ImportAndValidate` |
| 加一行数据 | 表里加一行填 ID → 导入 → 新资产出现在对应 `Definitions/` 子目录 |
| 加一列 | 表头加列 + 定义类加 `[CsvColumn]` 字段 → 全量重导入 |
| 加一张表 | `DefinitionImportMap.All` 加一条 + 新建定义类型（继承 `DefinitionBase`）+ 建表 |
| 只校验不导入 | `HeadlessTasks.ValidateOnly` |
| 全量重导 | `HeadlessTasks.ImportAndValidate`（含本地化与校验） |

## 故障排查

| 现象 | 原因与处理 |
|---|---|
| `CSV_COLUMN_MISSING` | 表头少了定义类声明的列（改名要看大小写与去空格后的拼写） |
| `CSV_COLUMN_UNMAPPED` | 表头多了一列而定义类没有对应字段：要么补字段，要么删列 |
| `DEF_ID_DUPLICATE` | 两张表或同一表内 ID 撞车，按报告里的路径定位 |
| `DEF_LOC_KEY_HAS_CHINESE` | 本地化 key 里写了中文，key 必须是 `a.b.c` 形式 |
| 表改了却没生效 | 走的是增量导入但哈希未变（例如只改了注释行外的东西）；跑全量导入确认 |
| `git status` 显示生成物已改而 `git diff` 为空 | 内容逐字节相同、只有 mtime 变了（ADR-012 的历史遗留或外部工具重写），`git update-index --refresh` 后即消失 |
| `.ps1`/CSV 中文乱码 | 带中文的 `.ps1` 必须存 UTF-8 with BOM；CSV 用 UTF-8（BOM 可有） |
