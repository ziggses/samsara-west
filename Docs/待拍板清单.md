  - [x] 破防额外伤害口径 `5% → 2%`（`BattleConfig._brokenBonusHealthRatio`）——这是本轮最关键的一处改动，理由见下
  - [x] 新增节奏校算器 `Editor/Tools/EncounterPacingEstimator.cs`（菜单 `SamsaraWest/数据/战斗节奏校算`）
  - [x] 新增断言 `Tests/EditMode/EncounterPacingTests.cs`：常规 4–6 回合、Boss 10–15 回合、单回合不得吃掉 Boss 25% 以上最大生命
  - [x] 同步《战斗数值 v1》第 5、6 节快照与校算
  - [x] 校算实测：常规 5–6 回合、隐藏 4 回合、Boss 12 回合；Boss 四阶段分别拿到 4 / 2 / 4 / 2 个完整回合
- **为什么动破防比例（原决策未预见）**：破防额外伤害是「目标最大生命 × 比例」且**按段数结算**，一回合最多 4 段。
  取 5% 时单回合峰值达 Boss 最大生命的 **28%**，而四阶段阈值最窄间距只有 25 个百分点——阶段会被整段跳过；
  同时把 Boss 血量从 1400 抬到 3800，回合数几乎不变（10 → 11），血量不再是节奏的主导变量。改为 **2%** 后单回合峰值降到 **17%**，
  四个阶段各拿到 2–4 个完整回合。两处断言都验证过「按旧口径会失败」。
- **被取代的动作**：原落地动作「Boss 阶段二阈值改 0.75」**不再执行**——那条是基于旧版两阶段（50% 触发）方案；
  现方案已是四阶段（1 / 0.7 / 0.4 / 0.15），并由「单回合峰值 ≤ 25%」这条断言统一兜住所有阶段边界，比逐个调阈值更直接。
- **顺序约束**：**已排在 P5 之后** —— 校算基准是首章真实猴妖编成。
- **未随本次决策处理**：《战斗数值 v1》第 7.3 节的四条遗留（破防伤害占比 55–68% 偏高、是否引入独立暴击率、相生是否参与战斗、隐藏遭遇的节奏目标）。**首轮仍为未决，第二轮已关闭其中三条**，见下。

## 第七轮补记（2026-10-08）：批次 4 · 防御落地

前三项待办的推进顺序是「先做已拍板的，再等设计的」。本轮把**已拍板但没写码**的**批次 4（防御）**做完了。

**口径（沿用第五轮补记，未改）**：减伤 **50%**、持续 **2 回合**、**占主行动**。第五轮把两件事留给了实现，本轮定为：

## 第九轮补记（2026-10-08）：战斗界面 · 诊断层视图

前两轮把界面回路做成了「能点的接口」（`BattleHudModel` + `BattleScreenController`，
两边都在 EditMode 里逐条锁死），但它们**没有任何视图**：`OnGUI` 一行都没有，
全工程 0 个 prefab、除 Bootstrap 外 0 个场景。本轮补上这一层——`BattleScreenView`，
**内核与回路都没改**（`RefreshCommands` 给什么就画什么，点了就转发）。

- **为什么是 IMGUI 诊断层**：与 `SkeletonBootScreen` 同一条理由，也沿用同一条先例——
  ADR-014 的正式界面（uGUI + TMP）需要一套带中文字形的字体资产，工程里还没有；
  若本层强依赖它，就会在「字体还没做」的现在一个字都画不出来，正好失去意义。
- **为什么自挂**：这一层要回答的问题是「界面拿到的这一手，点下去到底会怎样」。
  工程里没有任何流程会在一场仗开始时把它带起来，若要靠场景接线，漏挂时它会静默缺席。
  `[RuntimeInitializeOnLoadMethod]` 自挂之后，**用例不必先搭场景就能验它**。
- **它不含任何战斗规则**：单位行、意图预告、按钮、候选全部照抄 `BattleHudModel`；
  置灰的按钮**不转发**内核（界面已经知道它必然被拒，转过去只会往战斗日志里写「点了没用」）；
  拒绝理由也只是把 `BattleCommandOption.Rejection` / `LastResult.Rejection` 转述成文本键。
- **子选择归界面自己管**：`移动`／`换位`点开的是选落点／选同伴（`PickLabels` + `PickKeys`），
  随时可 `CancelPick()` 撤回；选目标的候选仍然只问驱动器。子选择不会替玩家推进战局。
- **服务重装后重新解析**：视图记下自己解析过的那张注册表，换了一张（组合根每次安装都新建一张）

- **诊断入口**：`StartDiagnosticBattle()`（默认 `ENC_CH01_001`）用**真实遭遇与真实队伍**开一场，

  （与 `ErrorOverlay` 同一条口径：正式包里不该有一个按键能凭空开战），`IsDiagnosticStartSupported`
  公开出来就是为了让用例不必猜这条规则。面板画在**左下角**，与左上角的骨架自检画面互不遮挡。
- **动了哪些文件**：新增 `UI/Runtime/Battle/BattleScreenView.cs`、`Tests/PlayMode/BattleScreenViewTests.cs`；

  5 条：不接线也能出现、用真遭遇开一场、拒绝顶掉进行中的战斗、**只靠点按钮把一整场仗打完**、

## 第十二轮补记（2026-10-08）：经文的每回合效果接进回合回路

上一轮把装备与经文的数值算进了进场快照，但其中两个字段没有「什么时候用」的落点——这一轮补上。
口径见 **ADR-018**，数值仍住在 `sutras.csv` 里。

- **时机**：「每回合」= **走完自己一手**，结算点在 `BattleSession.FinishTurn`，与状态持续伤害、
  破防计时、冷却递减同一处。速度高的单位一场仗里走的手数更多，于是这两个效果也随速度放大；
  被控跳过的那一手照样结算，与既有口径一致。
- **回灵**：走 `BattleUnit.RestoreSpirit`，照旧夹在灵力上限内，不会溢出；只对我方有意义。
- **苦修**：自己的回合收尾失血，**最多扣到剩 1 点、不致死**——代价类经文是「扣血换增益」的交易，

## 第十三轮补记（2026-10-08）：技能挂载——装备与经文带来的技能接进战斗

`equipment.csv` 与 `sutras.csv` 的 `passiveSkillId` 列此前是「填了也不会多出一手」的静默失效。
本轮把它落成**技能挂载**：口径见 **ADR-019**，技能本身仍住在 `skills.csv`（这一列是指向，不是新数据）。

- **挂载口径**：`passiveSkillId` = 「这件东西让我**多会哪一手**」。聚合层并进 `CharacterStatsSnapshot.SkillIds`：
  **自带技能在前、挂载的按在身清单顺序在后、重复只留第一次出现**。顺序就是优先级——规划器的平局判据
  与界面按钮顺序都读它，因此势均力敌时自带技能先被选中。
- **一处合成**：建单位时直接拿 `stats.SkillIds`，战斗侧不再自己拼一份「自带 + 挂载」。
- **坏引用只跳过那一手**：ID 查不到记 `LOADOUT_SKILL_MISSING`，查到的不是技能记
  `LOADOUT_SKILL_KIND_UNSUPPORTED`；同一件东西的**数值加成照旧生效**（坏的是那一手指向，不是整件装备）。
  重复**不报**：技能清单是集合语义，两处给同一手不改变任何行为。
- **挂载不带特权**：挂上来的技能与自带技能完全同权——占主行动、吃灵力、进冷却，被拒理由也同源
  （`NotEnoughSpirit`）。用例特意钉住这一条，谁哪天给它开了特权，这几条会先红。
- **真数据现状**：真表里**当前没有一行填过** `passiveSkillId`（装备与经文都是），所以本轮不动任何内容数据；
  挂载通路由用例搭场验证，内容填上那天即生效（填错则开战时自己报码）。
- **动了哪些文件**：`Data/Runtime/CharacterStats.cs`（快照加 `SkillIds` + 挂载校验）、
  `Battle/Runtime/BattleSetup.cs`（改装配好的清单）、`Battle/Runtime/BattleUnit.cs`（只补注释）、
  `Data/Runtime/Definitions/EquipmentDefinition.cs` 与 `SutraDefinition.cs`（tooltip 改回「带进战斗的技能」）、
  `Tests/EditMode/BattleLab.cs`（建场器补 `passiveSkillId`）、`Tests/EditMode/BattleSkillMountTests.cs`（新 10 条）、
  `Tests/EditMode/CharacterStatsTests.cs`（新 3 条）；`Docs/架构决策.md`（ADR-019）、`README.md`（测试基线、ADR 计数）。
  **伤害公式、回合回路、界面一行没改。**
- **测试**：EditMode **441 → 454**（新 13 条：`BattleSkillMountTests` 10 条接线与同权、
  `CharacterStatsTests` 3 条算术与坏引用码），全绿；PlayMode **22/22** 重跑过（建单位路径是公共路径）。
- **破坏验证**：两处。一是让挂载干脆不并进清单（`skills.Add` 那一行）→ **8 红**，正好是挂载相关的 8 条，
  只锁坏引用与「没挂就不多」的三条仍绿，符合预期；二是把挂载插到自带之前（`Insert(0, ...)`）→
  **恰好 4 红**，全是顺序断言。两处恢复后全绿。
- **仍未做**：**「被动技能」的被动语义**（要不要给 `skills.csv` 加「主动／被动」列、被动效果怎么表达）——
  已单列为第 8 条待拍板；`breakDamageBonus` 与 `resistElement`（等数值口径拍板）；
  **联合技**（批次 5，等设计）；装备的**运行期来源**（存档没有活持有者、也没有装备界面）；
  探索运行时、正式界面、战后结算依旧空白。

## 第十四轮补记（2026-10-08）：被动——身份登记一张新表，效果落在常驻状态上

装备与经文的 tooltip 从第一版起就写着「被动生效」，而工程里既没有「被动」这种定义，
也没有任何表达「不占行动、常驻生效」的载体（第十三轮只落了技能挂载，见 ADR-019 与上方第 8 条）。
本轮把这一层补上：口径见 **ADR-020**，新增**第 18 个定义种类**，表数 **17 → 18**。

- **被动只登记身份**：新增 `passives.csv`，与其它定义表同构，唯一与玩法有关的列是 `statusId`——效果写在那条状态上。
  分工只有一句话：**状态回答「会发生什么」，被动回答「这是谁给的」**。ID 前缀 `PSV_`（`IdRules` 第 18 条正则），
  映射写进 `DefinitionImportMap`，于是导入、校验、目录装配、本地化键扫描**全部自动认识它**，没有第二处表清单。
- **挂载列**：`equipment.csv` 与 `sutras.csv` 各加一列 `passiveId`，与 `passiveSkillId` **并列但互不相干**——
  同一件东西可以只挂技能、只挂被动，或两头都挂。
- **常驻是状态自己的一列**：`statuses.csv` 加 `permanent`（真源在 `StatusDefinition.IsPermanent`）。
  常驻状态在回合收尾**不递减 `RemainingTurns`、不到期、不进到期回收，但每回合量照旧结算**——
  「每回合回灵」这类被动正是靠后半句成立。**常驻是一个不递减的数，不是一个很大的数**（`durationTurns` 只作占位）。
- **两跳查表，只跳过坏的那一条**：聚合层把在身的 `passiveId` 并进 `CharacterStatsSnapshot.PassiveIds`
  （**集合语义**，重复只算一条；查不到记 `LOADOUT_PASSIVE_MISSING`、查到的不是被动记
  `LOADOUT_PASSIVE_KIND_UNSUPPORTED`）；战斗层在建单位那一刻做「被动 → 状态」两跳查表并 `ApplyStatus`，
  坏引用只跳过那一条并记 `GameLog.Error`。聚合层**不查 `statusId`、不施加状态**——它连 `StatusDefinition` 都不认识。
- **顺带定死一条顺序契约**：被动必须在 `BattleUnit.PrepareForBattle()`（满血满灵、无状态、无冷却）**之后**施加，
  因为归位会清空状态清单。于是 `BattleSession` **删掉了自己那一遍归位**：归位随「建单位那一刻」一次做完。
  这是本轮唯一一处**改动既有代码路径**的地方，也是最先被发现的那个坑。
- **与别的状态完全同权**：进状态清单、参与修正聚合、写进日志与界面状态条。今天的祛毒（`RemoveDebuffs`）
  只摘负面，因此摘不走增益类被动——这是**同权的结果，不是给被动的特权**。被动也**只作用携带者本人**，不是光环。
- **界面**：常驻状态**不画剩余回合数**（写个数字只会让人以为它要到期），由 `BattleStatusChip.IsPermanent` 转达。
- **真数据现状**：`passives.csv` 已有 2 行（`PSV_STAFF_FORCE` → `STS_STAFF_FORCE` 攻击 ×1.12；
  `PSV_STILLNESS_BREATH` → `STS_STILLNESS_BREATH` 每回合回灵 2），且 `EQP_STAFF_IRON` 与 `SUT_STILLNESS`
  已经把 `passiveId` 填上了——**这一轮的内容数据不是空的**，真实一件装备穿上就会多一条常驻状态。
  本地化键 `status.staff_force.*`／`status.stillness_breath.*`／`passive.*` 同步补齐。
- **动了哪些文件**：`Data/Runtime/Ids.cs`（`DefinitionKind.Passive = 18` + `PSV_` 正则）、
  `Data/Runtime/Definitions/PassiveDefinition.cs`（新）、`StatusDefinition.cs`（`permanent`）、
  `EquipmentDefinition.cs`／`SutraDefinition.cs`（`passiveId` + ID 校验）、`Data/Runtime/CharacterStats.cs`（`PassiveIds` + 两次挂载）、
  `Battle/Runtime/BattleSetup.cs`（两跳查表 + 归位顺序）、`BattleSession.cs`（删掉重复的归位）、
  `BattleUnit.cs`（归位契约注释 + 常驻不递减）、`BattleStatusInstance.cs`（`IsPermanent`）、
