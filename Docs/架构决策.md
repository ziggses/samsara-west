# 架构决策记录（骨架期）

记录《西游：第八十二难》工程底座的决策：**决定了什么、为什么、靠什么强制、代价与边界**。
决策一经落地并进测试即登记；推翻旧决策时不删条目，在末尾追加「已由 ADR-0xx 取代」。

相关文档：《数据管线》（`Docs/数据管线.md`）、《战斗数值 v1》（`Docs/战斗数值-v1.md`）。

## ADR-001 模块划分与依赖方向写成 asmdef，变成编译期错误

| 模块 | 职责 | asmdef references |
|---|---|---|
| `Core` | 服务定位、事件、时间、随机、对象池、日志 | `Unity.InputSystem` |
| `Data` | ID 规则、定义基类、CSV 解析、导入映射、校验 | Core |
| `Battle` | 伤害纯函数、战斗数值配置 | Core, Data |
| `Save` | 版本化 JSON 存档与迁移 | Core |
| `Localization` | 文本键服务、表资产、常量生成 | Core |
| `Flow` | 启动装配、场景与章节状态 | Core, Data, Localization, Save, Battle, `Unity.InputSystem` |
| `UI` | 本地化标签、运行期错误面板 | Core, Data, Localization, `Unity.TextMeshPro` |
| `Exploration` `Narrative` `Progression` `Economy` | 骨架占位（目录 + asmdef + 接口） | Core, Data |
| `Audio` | 骨架占位 | Core |
| `Editor` | 导入、校验、出包、工具窗口 | 全部运行时模块（`includePlatforms: ["Editor"]`） |
| `Tests/EditMode` | 单元测试 | TestRunner + Editor + 运行时模块（`UNITY_INCLUDE_TESTS`） |
| `Tests/PlayMode` | 场景级测试 | TestRunner + 运行时模块（**不含 Editor**） |

- **为什么**：文档里的依赖约定是君子协定，asmdef 里的依赖是编译错误。
- **强制**：asmdef `references`；`Tests/EditMode/ProjectSkeletonTests` 另外断言关键依赖，防止有人往 `Core` 里加 `Data` 引用。
- **代价**：跨模块取数据必须走 `Data` 的契约类型；新增模块要同时建目录、asmdef 与骨架测试断言。

## ADR-002 服务定位，而非单例泛滥，也不引 DI 框架

`Core/Runtime/Services.cs`：

- `IService { OnRegistered(IServiceRegistry); OnUnregistered(); }`
- `Register<T>(T)` 同时以**契约类型与具体类型**注册；重复绑定到不同实例抛 `InvalidOperationException`
- `Resolve<T>()` 未注册抛 `ServiceNotRegisteredException`；另有 `TryResolve/IsRegistered/Unregister/Clear/RegisteredTypes`
- `Clear()` **逆序**调 `OnUnregistered()`，依赖方先于被依赖方释放
- 门面 `GameServices.Install/Uninstall/Registry`

**跨场景不丢服务**：服务是纯 C# 对象，不挂场景。挂 `DontDestroyOnLoad` 的是 `Flow/Runtime/GameBootstrap.cs` 的引导对象（重复实例自毁，`OnDestroy` 里 `Registry.Clear()` + `Uninstall()`）。

**不引 DI 框架**：当前十余个服务、四个消费方，容器只会把装配代码挪个位置，却带来容器语义与调试成本。用「解析失败即抛异常」换掉「某处为 null 到处空引用」。

**边界**：每个服务必须有「注册 → 解析 → 卸载」的 EditMode 覆盖；运行时模块**禁止**新增静态单例。

## ADR-003 模块间只走类型化事件总线，带频道与弱引用

`Core/Runtime/Events.cs`：

- `EventChannel` 13 项（Core/Data/Flow/Battle/Exploration/Narrative/Progression/Economy/UI/Save/Localization/Audio/Tools）
- `IEventBus : IService`：`IDisposable Subscribe<T>(Action<T>)`、`Subscribe<T>(EventChannel, Action<T>)`、`Publish<T>(T)`、`Publish<T>(EventChannel, T)`、`ClearChannel(EventChannel)`、`ClearAll()`、`SubscriberCount`
- 退订：`Dispose()` 订阅句柄，批量用 `SubscriptionBag`
- 弱引用：目标是普通类/服务时用 `WeakReference`；**lambda、闭包、静态方法用强引用**（无法可靠判活）——注册闭包即自负退订责任
- 发布时清理死订阅；单个订阅者抛异常不中断发布，异常落 `GameLog.Error`

**代价**：事件是运行期契约，编译期不检查有无订阅者，因此关键事件要求消费方有测试。

## ADR-004 可复现随机：PCG 命名流 + 快照

`Core/Runtime/Random.cs`，自实现 **PCG-XSH-RR 32**，不用 `UnityEngine.Random`。

- `GetStream(name)`、`Reseed(ulong)`、`SnapshotAll()` / `RestoreAll(state[])`
- 命名流常量 `RandomStreams.Battle/Loot/Narrative/Exploration/Economy`
- 初始状态 `splitmix64(seed ^ FNV1a(流名))`，**流名只影响初始状态**：改抽卡逻辑不影响剧情序列
- `RandomStreamState` 带 `Name/State/Increment/DrawCount`，`Restore` 校验流名一致
- 工具：`NextUInt/NextFloat/NextInt/NextDouble/Chance/Pick/Shuffle`

**用途**：战斗重放、存档续玩、测试确定性（同种子同结果）。

## ADR-005 时间抽象：可注入的 manual 模式

`Core/Runtime/Time.cs`：`ITimeService` 暴露 `Elapsed/Delta/RealElapsed/Scale/IsPaused/IsManual` 与 `Pause/Resume/Advance/Tick/Reset`。
manual 模式下除 `Advance(seconds)` 以外的驱动调用抛 `InvalidOperationException`，把「时间」变成测试输入。
驱动者 `GameClockDriver` 用 `[DefaultExecutionOrder(-10000)]` 在 `Update` 里 `Tick(Time.unscaledDeltaTime)`。

## ADR-006 对象池只服务高频短命对象

`Core/Runtime/Pooling.cs`：`ObjectPool<T>`（`Get/Release/Prewarm/Clear` + `CountActive/CountInactive/TotalCreated`）、`PrefabPool`（多实例 `Spawn(pos, rot)`）、`PoolService`（`GetOrCreate<T>/GetOrCreatePrefab/TryGet/ClearAll`）。
适用范围：特效、飘字、敌人实例。**不对低频对象做池**（YAGNI，池本身有状态成本）。
已知坑见 README 第 1 条：`DestroyItem` 刻意不用空条件调用（Mono 下会挂死主线程），**不要改回去**。

## ADR-007 日志分层分频道，环形缓冲 + 文件降级

`Core/Runtime/Logging.cs`：`LogLevel`（Trace…Off）、`LogChannel`（同 13 项）、静态门面 `GameLog`（`Configure/AddSink/RemoveSink/EnsureInstalled/Snapshot/Trace…Fatal`）。

- `RingBufferSink` 容量 2048，供日志控制台与错误面板回溯
- `FileLogSink` 写 `persistentDataPath/Logs`，`SubsystemRegistration` 时 `AutoInstall`；WebGL 自动降级
- `ILogSink` 由 `UI/Runtime/ErrorOverlay.cs` 实现，**仅在 Editor 与 Development Build** 生效，发布版只留文件日志
- 纪律：不打印个人信息与大对象；高频路径不拼字符串（用结构化字段）

## ADR-008 数据以 ScriptableObject 为唯一真源，CSV 只是输入面

`DefinitionBase` 定义统一契约：`Id / DisplayNameKey / DescriptionKey / Tags / Version / Icon` + `abstract DefinitionKind Kind` + `virtual Validate(ValidationReport)`。
所有 ID 规则集中在 `Data/Runtime/Ids.cs` 的 `IdRules`（按 `DefinitionKind` 查编译好的正则），**禁止在业务代码里散落 ID 正则**。
反射（`CsvDefinitionMapper`）只在**编辑器期**使用，不进运行时热路径；运行时只认资产。

## ADR-009 本地化全量走 key，缺键不回退中文

`LocalizationService`：`HasKey/Get/Format(key, params)/EnumerateKeys/DescribeMissingKeys`。
缺键返回 `[[key]]` 并记警告——**绝不回退显示中文**，否则缺键会被中文掩盖到上线。
键表 `Localization/Tables/localization-zh-Hans.csv` 导入后生成 `Localization/Generated/LocalizationKeys.g.cs` 常量类，代码里写 `LocalizationKeys.Xxx`。
兜底：`HardcodedChineseScanner` + 白名单 `Localization/scan-ignore.txt`，以 Headless 入口在流水线上跑（命中退出码 3）。

## ADR-010 存档版本化，迁移是内部逐版本步进

`Save/SaveData.cs`（`Version/ChapterIndex/MapId/GridX/GridY/RandomSeed/Gold/PlayTimeSeconds/Flag*/心念三轴/队伍/任务/背包/装备分配`）+ `SaveService`：

- `LatestVersion = 3`；`TryLoad` 内调私有 `Migrate(data)` 逐版本步进（v0→按 v1 视之；v1→心念单值拆三轴，负值归 0；v2→装备从扁平列表搬进「成员 × 槽位」并清空旧字段，见 ADR-015）
- `data.Version > LatestVersion` **拒绝加载**，不猜测未来字段
- 写盘用临时文件 + `File.Replace/Move` 原子替换，路径 `saves/slot_XX.json`

**不抽可插拔迁移接口**：当前只有三个版本，接口是为想象中的需求付成本；新增版本时**必须同时**加迁移分支与测试。

## ADR-011 构建与无头入口统一为 executeMethod

- 出包：`SamsaraWest.Editor.BuildPipeline.BuildPipeline.BuildWindows` / `BuildWebGl`（菜单 `SamsaraWest/出包/*`，失败退出码 1，产物落 `Builds/`）
- 无头：`HeadlessTasks.ImportAndValidate`（全量导入 + 校验，0/2）、`ValidateOnly`（0/2）、`ScanHardcodedChinese`（0/3）
- 退出码同时以 `[CI] exit_code=` 写日志，便于流水线抓取
- **批处理串行**：无头 Unity 不可并发跑同一工程（会写坏 `Library`），脚本检测到并发直接拒绝

## ADR-012 生成物一律「内容没变就不落盘」

`SetDirty` + `SaveAssets` 会把内容没变的资产整份重写，mtime 一变 `git status` 就报假改动（`git diff` 却是空的）。
因此清单、数据目录、本地化表、本地化常量类全部按「内容无变化则跳过写盘」实现（范式见 `LocalizationImporter.WriteConstants`）。
**纪律**：新增生成物照此办理，否则每次初始化都会留下假改动。测试套件里的 `ImportAll(force: true)` 会改时间戳，属预期。

## ADR-013 明确不做的事（骨架期留白）

不引 ECS、DI 框架、第三方事件库、第三方本地化包；`Narrative` 不接 Ink（属垂直切片阶段），只留目录与 asmdef。
视觉锚点锁定为：32×32 像素素材、480×270 基准界面稿、参考分辨率 1920×1080（×4）、Linear 色彩空间；角色与瓦片世界像素尺寸**暂不锁定**。

**已由 ADR-014 取代**：本条原含「不预设 UI 框架与窗口管理」，该留白已于 2026-09-24 提前收口（P8）。

## ADR-014 界面框架定为 uGUI + TextMeshPro

（P8 决策：不在垂直切片期再定，骨架期即收口。）

- 正式界面一律 **uGUI**：`CanvasScaler` 用 Scale With Screen Size，参考分辨率 **1920×1080**（480×270 ×4），一律锚点布局，不写死像素位置。
- 文本一律 **TextMeshPro**，取词走 `LocalizationService`，Prefab 里禁止出现中文（由 `HardcodedChineseScanner` 兜底）。
- 编辑器工具（数据校验窗口等）继续用 **UI Toolkit**：只服务开发期，不进包。
- 8 个装备栏位的展示顺序与文案键统一取 `EquipmentSlots.DisplayOrder` 与 `EquipmentSlots.LocalizationKey`（ADR-015），不在界面里自行排列表。

- **为什么**：uGUI 在 2022.3 的成熟度、图集与九宫格工作流、美术与策划的上手成本都最优；UI Toolkit 的运行时在 2022.3 仍有世界空间、图集与动画的缺口，骨架期押注它等于把风险推迟到内容生产阶段。
- **代价**：两套 UI 技术并存，因此必须守住上文的边界（工具用 UI Toolkit、正式界面用 uGUI）。
- **边界**：Prefab 与场景属内容生产期产物，骨架期只锁约定与栏位口径，不产出界面资产。

## ADR-015 装备 8 槽；存档 v3 用「成员 × 槽位」表达

（P2 决策扩槽，P10 随之迁移；P3 数量口径为 200 件。）

- `EquipmentSlot` 核定为 8 槽：武器 / 副手 / 头盔 / 护甲 / 护腕 / 腿部护具 / 法宝 / 经文。
- **枚举数值只增不改**：`OffHand=5`、`Helmet=6`、`Bracer=7`、`Legging=8` 追加在原 4 项之后——已生成的 SO 资产按整数序列化，改动既有数值会让旧资产串位。
- 展示顺序与文案键**不由枚举数值隐含**，统一取 `EquipmentSlots.DisplayOrder` / `EquipmentSlots.LocalizationKey`；键与文案表的一致性由 `EquipmentSlotTests` 钉住。
- 存档 v3：`List<EquipmentAssignment>`（`CharacterId`/`SlotId`/`ItemId`）取代 v2 的扁平 `EquippedItemIds`。`SlotId` 用字符串名而非枚举，因为 `Save` 不依赖 `Data`（ADR-001）。迁移按队伍顺序把旧装备落到武器栏，随后**清空**旧字段——不留双重真源。
- 校验：`SaveService.Validate` 拦「字段缺失」与「同成员同槽位重复」。

- **为什么**：8 槽是内容侧的真实需求（防具按部位细分）；此刻改的成本只在骨架期，晚改要同时动数据、存档、界面与已产出的 200 件装备。
- **代价**：需 4 类新部位素材；枚举数值与展示顺序不再一致，读代码必须知道去 `EquipmentSlots.DisplayOrder` 取顺序。

## ADR-016 战斗数学是纯函数，掷骰由调用方注入；五行只有一处真源

（2026-09-24 第二轮数值改定：独立暴击 + 相生参与伤害 + 破防比例 5%→2%。口径与校算见《战斗数值 v1》。）

- `DamageCalculator` **不碰 Unity 对象、不读时间、不用全局随机**：伤害是入参与出参的纯函数，公式的九步顺序即实现顺序。
- **暴击掷骰由战斗流程传入**（`ComputeSkillTotal` 收 `IReadOnlyList<float> criticalRolls`，逐段一一对应），掷骰从「战斗」命名随机流取出。因此单测与节奏校算不传掷骰（`DamageInput.NoCritical`）即可拿到确定性结果，而运行期仍是概率行为。
- **五行关系只有一处真源**：`ElementRules.Relate` 返回 `克制 / 借势 / 同属 / 资敌 / 被克 / 无属性`，五类关系把 25 种配对分完；战斗代码禁止自己写元素 switch。
- **克制与暴击是两件事**：`IsCritical` 只表示暴击掷骰命中，`IsElementAdvantage`（读 `ElementRelation`）才表示「这一手元素打对了」。战斗日志可分开显示。
- **数值全部外置**：倍率、护体、破防时长、暴击率等只存在于 `BattleConfig_Default.asset` 与 CSV，不写进 C# 常量；`DefaultAsset_MatchesCodeDefaults` 断言资产与代码默认值一致，避免「测试读默认值、运行期读资产」造成的静默漂移。

- **为什么**：纯函数让「回合数校算」与「单元测试」共用同一条公式，数值改动的影响面可被断言立刻照出来；掷骰注入是纯函数与概率玩法的唯一折中点。
- **代价**：战斗流程必须自己管随机流并负责逐段掷骰；忘记传掷骰会得到「永不暴击」的确定性结果，这是刻意的默认值而非缺陷。

## 未决事项

1. ~~战斗节奏与数值目标不一致~~ → **已决并已落地（2026-09-24）**：目标维持「常规 4–6 回合、Boss 10–15 回合」，按《战斗数值 v1》方向一（抬敌人数值、不动角色手感）执行。首章实测：常规 5–6 回合、隐藏 4 回合、Boss 12 回合。落地时额外发现并修正了一处口径缺陷——破防额外伤害由「最大生命的 5%」降为 **2%**（5% 时单回合峰值达 Boss 最大生命的 28%，会整段跳过阶段；详见《战斗数值 v1》第 7.2 节）。校算与断言见 `EncounterPacingEstimator` 与 `EncounterPacingTests`。
2. ~~`Editor` 依赖全部运行时模块~~ → **已决（P9）**：维持现状，出包时间变敏感时再拆细。
3. ~~UI 层无框架~~ → **已决（P8）**：见 ADR-014。
4. ~~「克制即暴击」是否够用、相生是否参与战斗~~ → **已决并已落地（2026-09-24，第二轮）**：新增独立暴击 `CriticalChance` 0.10 / `CriticalMultiplier` 1.5（**逐段**掷骰，`IsCritical` 从此只表示真暴击，克制改用 `IsElementAdvantage`）；相生以「借势 ×1.15 / 资敌 ×0.85」参与**伤害**计算，与相克共用 `ElementRules.Relate`。
