# 战斗数值 v1

任务书只写了五行关系、没给数字，本文给出**一版有依据的口径**，附带输出与回合数校算，**供人工审改**。
所有数值都外置在资产与 CSV 里，改数值不需要改代码、不需要重编译。

- 口径参数：`Battle/Config/BattleConfig_Default.asset`（定义类 `Battle/Runtime/BattleConfig.cs`）
- 单位数值：`Data/Tables/characters.csv`、`enemies.csv`、`skills.csv`、`statuses.csv`、`bossphases.csv`
- 公式实现：`Battle/Runtime/DamageCalculator.cs`（纯函数，不碰 Unity 对象、不读时间、不用全局随机）
- 断言：`Tests/EditMode/BattleDamageTests.cs` 把本文口径逐条钉死，改数值表会立刻看到影响面

## 1. 伤害公式（运算顺序即实现顺序）

```
1) raw = power + 攻击 × AttackScale(1.0) − 防御 × DefenseScale(0.5)
2) raw ×= (1 + 攻击修正)              // 状态/装备的百分比修正
3) raw ÷= (1 + max(0, 防御修正))       // 走分母，避免出现负数与除零式爆炸
4) raw ×= 五行倍率
5) 若目标破防：raw = raw × 1.5 + 目标最大生命 × 0.05
6) raw ×= 0.85 ^ 段序号               // 第 0 段不衰减
7) raw ×= max(0, 承伤修正)            // 易伤/抗性
8) 伤害 = max(1, RoundToInt(raw))     // 下限 1；取整是银行家舍入（正好 .5 时进偶数）
```

| 参数 | v1 值 | 说明 |
|---|---|---|
| `AttackScale` / `DefenseScale` | 1.0 / 0.5 | 攻击全额、防御半额，保证高防敌人可磨但不免疫 |
| `MinimumDamage` | 1 | 伤害下限，任何情况下不出现 0 与负数 |
| `MultiHitDecay` | 0.85 | 多段攻击第 n 段系数 0.85ⁿ |

## 2. 五行倍率

相克环：**金克木、木克土、土克水、水克火、火克金**（`Data/Runtime/SharedEnums.cs` 的 `ElementRules`，业务代码禁止自己写 switch）。

| 关系 | 倍率 | 例 |
|---|---|---|
| 克制 | **1.5** | 金→木、木→土、土→水、水→火、火→金 |
| 被克 | **0.75** | 上表的反向 |
| 同属 | 1.0 | 火打火 |
| 任一方无属 | 1.0 | `None` 一律中性 |
| 相生（木生火等） | 1.0 | v1 **不给相生加成**；`ElementRules.Generates` 留给治疗/增益后续使用 |

当前实现把「克制」同时视作暴击标记（`DamageResult.IsCritical => 五行倍率 > 1`），**没有独立的暴击率字段**。若要真暴击，需新增 `CritChance/CritMultiplier` 两个参数。

## 3. 护体值与破防

- **护体值**：单位的 `breakThreshold`（角色 24–36，杂兵 16–20，Boss 40）
- **破防削减**：`ComputeBreakDamage(breakDamage, hitCount, breakModifier) = breakDamage × hitCount × breakModifier`
  即**多段技能的每一段都算削减**——这就是「多段技能更适合破防」的机制来源
- **破防效果**：承伤 ×1.5，且**每次受击**额外加 `目标最大生命 × 5%`
- **破防时长**：2 回合（`BrokenDurationTurns`）
- 骨架期只实现纯函数；护体重置时机、破防进入/退出的状态机由后续战斗流程实现

## 6. 输出与回合数校算

基数：`raw = power + 攻 − 防×0.5`，取整为银行家舍入。

| 场景 | 计算 | 结果 |
|---|---|---|
| 悟空棍击 → 强盗 | 8 + 22 − 3 = 27，五行中性 | **27**（60 血 ÷ 27 → **3 次打空一条血**，与 `BattleConfig` 注释一致） |
| 悟空棍击 → 弓手 | 8 + 22 − 2 = 28，火克金 ×1.5 | **42** |
| 八戒钉耙 → 强盗 | 段0 (14+18−3)×0.75 = 21.75 → 22；段1 ×0.85 → 18 | **40 / 次（2 敌）** |
| 沙僧流沙 → 狼 | 12 + 17 − 2.5 = 26.5，水克火 ×1.5 | **40（全体）** |
| 悟空棍击 → 破防的强盗 | 27×1.5 + 60×0.05 = 43.5 | **44**（+63%） |
| 悟空怒吼 → 破防的头目 | 39×1.5 + 160×0.05 = 66.5 | **66**（+69%） |

回合数推算（四人出手，唐僧只上护体/治疗不计输出）：

| 遭遇 | 编成 / 总血 | 队伍每回合输出 | 推算回合 |
|---|---|---|---|
| `ENC_CH01_001`（常规） | 强盗 ×2 = 120 | 沙僧 26×2 + 悟空 27 + 八戒 40 ≈ **119** | **1–2** |
| `ENC_CH01_002`（常规） | 强盗 + 狼 = 130 | ≈ 119（狼被沙僧克制时更高） | **2** |
| `EENC_CH01_001`（精英） | 弓手 + 强盗 ×2 = 170 | 沙僧 27×3 + 悟空 42 + 八戒 40 ≈ **163** | **2** |
| `BENC_CH01_001`（Boss） | 头目 160 | 39 + 37 + 24 ≈ **100**（破防后 ≈ 181） | **1–2** |

破防速度：头目护体 40，悟空怒吼 22 + 八戒钉耙 18 + 沙僧流沙 8 = **48/回合 → 首回合即破**，破防窗口吃掉整个战斗。

**结论：与 `BattleConfig.cs` 注释里的目标（常规 4–6 回合、Boss 10–15 回合）明显不符**：当前数值下节奏偏快，且 Boss 第二阶段（血量 50% 触发 `BSP_CH01_001_P2`）在队伍首回合集火破防（单回合 ≈ 181）时会被一回合打穿，可能只存在一回合甚至来不及生效。

## 7. 待人工审改（三选一，选定后我按选项改表并重跑校算）

1. **抬敌人血量与护体**（推荐，不动角色手感）：强盗 150 / 弓手 125 / 狼 175 / 头目 400；护体 强盗 45 / 弓手 35 / 狼 40 / 头目 120；Boss 阶段二阈值 0.5 → 0.75。预期：常规 4–5 回合、精英 5–6、Boss 10–13。
2. **降队伍输出**：把五行倍率与公式保留，角色攻击力整体下调约 35%。代价是「3 次打空一条血」的锚点与全部校算作废，需重算。
3. **承认快节奏**：保留数值，把 `BattleConfig.cs` 的目标注释与本文档改为「常规 2 回合、精英 2–3、Boss 3–4」，同时把 Boss 阶段二阈值提到 0.75 以保证玩家看到二阶段。

另需确认的两处口径：

- 「克制即暴击」是否够用，还是要引入独立暴击率与暴击倍率（会新增两个可调参数与对应断言）。
- 相生是否参与战斗（v1 只用于后续治疗/增益），若参与，倍率与生效条件需另定。

## 8. 变更流程

1. 改 `Data/Tables/characters.csv` / `enemies.csv` / `skills.csv` / `statuses.csv`；参数改 `BattleConfig_Default.asset`。
2. 重新导入：`HeadlessTasks.ImportAndValidate`（或菜单 `SamsaraWest/数据/数据工具窗口`）。
3. 跑测试：`Tools\run-tests.ps1 -Platform All`；`BattleDamageTests` 会指出受影响的断言，数值确实有意变更时，**先改断言并确认它变红再变绿**。
4. 同步更新本文档的「首章数值快照」与「校算」两节。
