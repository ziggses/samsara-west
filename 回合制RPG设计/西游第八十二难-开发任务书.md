# 《西游：第八十二难》开发任务书

**版本**：v0.1  
**产品形态**：单机、剧情向、现代回合制 RPG  
**首发平台**：Windows PC，Steam 优先  
**引擎**：Unity 2022.3 LTS（先沿用现有稳定版本，完成垂直切片后再评估 Unity 6）  
**主线规模**：8 章，6–8 小时通关  
**首版内容**：4 名常驻队员、8 个主线 Boss、20–24 种普通敌人、80 件装备/道具、60 个技能、12–20 个支线事件  
**联网/配音**：不联网；中文配音不作为首发条件，可保留关键角色战斗语音  
**开发基准**：4–6 人核心团队，16–22 个月完成 1.0；单人开发预计 24–36 个月

# 一、产品范围

## 1.1 首发必须有的内容

| 模块 | 首发目标 |
|---|---|
| 主线 | 序章 + 8 章，包含 4 种主线结局 |
| 队伍 | 阿玄、孙悟空残魂、猪八戒、沙悟净，全部可培养 |
| 战斗 | 回合制、3×2 阵型、行动顺序、破防、五行、状态、联合技 |
| 探索 | 方格地图、可见敌人、宝箱、机关、NPC、传送点 |
| 剧情 | 8–12 万字主线和 2–4 万字支线 |
| 成长 | 等级、技能树、装备、经文套装、队伍关系 |
| 经济 | 灵蕴、功德、商店、锻造、资源兑换 |
| 支线 | 12–20 个支线，其中至少 12 个影响结局或角色能力 |
| UI | 主菜单、战斗 HUD、队伍、背包、技能、任务、地图、图鉴、设置 |
| 存档 | 手动存档、自动存档、章节存档、结局存档 |
| 平台 | 键鼠和手柄基础支持、中文界面、可扩展本地化结构 |

## 1.2 首发明确不做

- 联网、联机合作、排行榜。
- 全程配音、大量嘴型动画。
- 程序化大地图。
- Roguelike 随机局内 Build。
- 无尽模式、每日挑战、创意工坊。
- 主机移植。
- 多语言首发。
- 超过 20 小时的超长主线。
- 每个 NPC 独立 3D 模型。

# 二、核心玩法设计

## 2.1 探索循环

```text
进入地区
  ↓
探索方格地图、触发事件
  ↓
可见敌人或剧情战斗
  ↓
战斗胜利、获得灵蕴与道具
  ↓
城镇休整、购买装备、推进支线
  ↓
进入章节 Boss 区域
  ↓
关键选择、改变因果
  ↓
进入下一章
```

### 探索规则

- 采用 8 方向方格移动，移动平滑但不做动作游戏操作。
- 普通敌人在地图上可见，接触后进入战斗，不采用纯随机遇敌。
- 每张地图有 1–3 个解谜机关、2–5 个宝箱、若干 NPC 和隐藏事件。
- 地图之间通过场景门、渡口、传送阵和章节节点连接。
- 关键战斗前自动补满队伍，允许玩家保留一次战术调整。
- 提供“战斗速度”“自动战斗”“重复上一回合”等现代便利功能。

## 2.2 战斗规则

### 基础行动

每个角色每回合拥有：

- 1 次主要行动。
- 1 次移动或换位。
- 若干被动反应。
- 消耗“心念”释放终极技能。

角色可以使用：

- 攻击：普通攻击、武器技能。
- 法术：消耗法力或灵力。
- 道具：药品、符箓、投掷物。
- 防御：减少伤害、恢复状态。
- 换位：改变前后排和相邻关系。
- 逃跑：普通战斗可用，Boss 战禁用。
- 联合技：满足角色关系和站位条件时触发。

### 行动顺序

- 按速度值排列初始顺序。
- 使用加速、减速、打断和延迟行动改变顺序。
- 普通敌人和 Boss 的关键技能提前显示“意图”。
- 玩家可通过破防、控制或反制打断敌人的蓄力技能。

### 破防与五行

- 敌人有护体值，受到正确属性或破防技能后降低。
- 护体归零后进入“破相”状态，承受额外伤害并中断蓄力。
- 五行关系为：金克木、木克土、土克水、水克火、火克金。
- 属性克制不只是加伤害，还可以改变护体、状态和 Boss 阶段。
- 每个角色拥有主属性，但技能可通过经文或装备改变属性。

### 状态效果

首批状态控制在 16 种以内：

- 灼烧、冻结、麻痹、中毒、流血。
- 虚弱、破甲、减速、沉默、封印。
- 护盾、再生、反击、嘲讽、洞察、隐身。

状态效果必须满足：

- 有清晰图标。
- 有持续回合数。
- 有可追踪的来源。
- 有明确的解除方法。
- Boss 不能免疫所有控制，否则战斗会退化成数值对拼。

## 2.3 队伍与角色成长

每名角色拥有：

- 1 个核心资源。
- 2 条技能分支。
- 12 个主动技能。
- 4 个被动技能。
- 1 个终极技能。
- 4 件装备槽：武器、防具、法宝、经文。
- 3 个可选战斗定位。

角色差异示例：

| 角色 | 核心资源 | 定位 |
|---|---|---|
| 阿玄 | 因果 | 全能、复制、联合技 |
| 悟空残魂 | 斗势 | 爆发、破防、连击 |
| 猪八戒 | 饱食 | 坦克、反击、群体嘲讽 |
| 沙悟净 | 业障 | 护盾、控制、资源恢复 |

## 2.4 经文系统

经文是跨角色装备，提供 2 件套和 4 件套效果：

- 火经：灼烧、爆发。
- 寒冰经：冻结、控制。
- 雷经：连击、麻痹。
- 金刚经：护盾、反伤。
- 神行经：速度、闪避、行动顺序。
- 吞天经：吸血、击杀恢复。
- 聚灵经：灵力恢复、技能冷却。
- 如意经：万能补位，但效果弱于专职经文。

经文不能只加百分比。每条经文至少提供：

- 一个基础属性。
- 一个可感知的战斗规则。
- 一个 2 件套效果。
- 一个 4 件套效果。
- 一个与角色技能的联动点。

## 2.5 经济系统

| 货币 | 作用域 | 主要用途 |
|---|---|---|
| 灵蕴 | 局内或章节内 | 买药、符箓、临时装备和补给 |
| 功德 | 永久存档 | 解锁经文、角色被动、洞府功能和图鉴奖励 |
| 妖丹 | 装备材料 | 锻造、升级和重铸装备 |
| 缘分 | 关系资源 | 提升角色信任、解锁联合技和后日谈 |

禁止出现一种货币同时承担全部成长功能的设计。

# 三、技术架构

## 3.1 模块划分

| 模块 | 职责 |
|---|---|
| Core | 启动、服务定位、事件、时间、对象池、随机数 |
| Data | ScriptableObject/CSV 数据定义与导入 |
| Flow | 启动、场景切换、章节状态、存档流程 |
| Exploration | 方格移动、交互、机关、触发区、地图切换 |
| Battle | 战斗状态机、行动队列、技能、伤害、AI、Boss 阶段 |
| Narrative | Ink 对白、事件条件、变量、任务状态 |
| Progression | 等级、技能、装备、经文、队伍关系 |
| Economy | 货币、商店、掉落、锻造和兑换 |
| UI | 主菜单、HUD、战斗界面、背包、任务、设置 |
| Save | 存档序列化、槽位、迁移和校验 |
| Tools | 数据校验、战斗模拟、地图检查、文本导入 |
| Audio | 音乐、音效、动态战斗音乐 |

## 3.2 关键技术选择

- 对话分支使用 Ink，禁止完全自研可视化对白语言。
- 数据配置优先使用 ScriptableObject；大批量表格使用 CSV/Excel 导入。
- 地图使用 Tilemap + 自定义交互组件。
- 战斗使用纯数据驱动状态机，不把逻辑写死在角色脚本。
- RNG 使用可记录种子的随机服务，方便复现战斗和测试。
- 存档使用带版本号的 JSON，必须支持旧版本迁移。
- 本地化从第一天使用 key，不在 UI 中硬编码中文。
- UI 使用事件驱动，禁止 UI 直接改战斗内部状态。

## 3.3 数据对象

首发至少需要以下数据定义：

- CharacterDefinition
- SkillDefinition
- StatusDefinition
- EnemyDefinition
- EncounterDefinition
- BossPhaseDefinition
- ItemDefinition
- EquipmentDefinition
- SutraDefinition
- QuestDefinition
- DialogueAsset
- MapDefinition
- InteractableDefinition
- LootTableDefinition
- ShopDefinition
- RecipeDefinition
- EndingConditionDefinition

所有数据必须有唯一 ID、显示名、描述、图标、标签、版本和校验规则。

# 五、里程碑与排期

## 5.1 总体节奏

| 阶段 | 目标 | 建议周期 | 通过条件 |
|---|---|---:|---|
| M0 预制作 | 锁定范围、技术方案和美术样板 | 4 周 | 垂直切片任务全部明确 |
| M1 战斗原型 | 证明回合制战斗好玩 | 8 周 | 一场 19 回合以内的战斗有明确决策 |
| M2 垂直切片 | 第一章可完整游玩 | 12–16 周 | 30–45 分钟内容达到可展示质量 |
| M3 Alpha | 核心系统完成，前四章可串联 | 16–20 周 | 无阻塞性 Bug，内容管线稳定 |
| M4 内容完成 | 八章、支线、Boss、结局完成 | 24–32 周 | 主线从序章到结局可通关 |
| M5 Beta | 平衡、文本、性能、兼容性 | 10–12 周 | 外部试玩不再出现高优先级问题 |
| M6 上线 | 商店页、构建、宣传素材 | 4–6 周 | 可发布候选版本冻结 |

## 5.2 推荐开发顺序

1. 先做战斗和内容工具，不先做大量地图。
2. 第一章必须能独立展示核心玩法、剧情选择和最终质量。
3. 第二章开始必须只使用正式管线生产，避免手写特例。
4. 第四至第六章可以并行制作地图、战斗和剧情。
5. 最终章最后做，避免最后选择被前期内容反复推翻。
6. 所有支线必须先确认奖励与结局影响，再写正文。

# 九、美术与音频工作流

## 9.1 角色生产

每名主要角色至少包含：

- 全身立绘 1 张。
- 表情头像 6 个。
- 地图待机/移动动画。
- 战斗待机、攻击、受击、施法、倒地。
- 3–5 个技能特效。
- 1 个终极技能演出。

## 9.2 敌人生产

普通敌人按模板分级：

- A 类：有独立模型、独立技能，用于章节代表敌。
- B 类：复用骨架和动画，换材质与队伍组合。
- C 类：数值与行为变体，用于填充路线和支线。

目标：20–24 个敌人的视觉清晰度，40 种以上的战斗变体。

## 9.3 场景生产

- 所有地图采用模块化素材。
- 每种地区只新建 30%–50% 新素材，其余复用通用组件。
- 每个区域至少有一个标志性视觉物，例如花果山灵石、五行山封印柱、流沙河业镜。
- 地图必须优先服务战斗和叙事，不为纯观感造无用空间。

## 9.4 音频优先级

1. 战斗命中、受击、破防、死亡。
2. 技能和状态音效。
3. 地图交互和脚步。
4. 8 章 BGM。
5. Boss 阶段切换音乐。
6. 关键战斗语音。

# 十、测试与验收

## 10.1 战斗验收

战斗系统满足以下条件才算可用：

1. 玩家不需要工具提示也能通过敌人意图做决定。
2. 至少 70% 的战斗在 8–15 回合内结束。
3. Boss 战 15–25 回合结束。
4. 每个角色至少有 3 种有效打法。
5. 不存在某个技能在所有战斗中都优于其他选择。
6. 自动战斗可以处理普通战斗，但无法处理 Boss。
7. 战斗加速不会造成状态错乱或漏结算。
8. 任何状态都能明确显示来源、层数和剩余回合。

## 10.2 剧情验收

1. 关键选择发生前，玩家能理解当前问题。
2. 选择发生后 1–2 章内能看到结果。
3. 每名队友至少有 1 次冲突和 1 次主动帮助主角的关键时刻。
4. 最终结局必须至少受 3 个前期选择影响。
5. 不出现“玩家只能选对”或“所有选项都无差别”的伪选择。

## 10.3 性能验收

- 1080p、中档显卡稳定 60FPS。
- 战斗加载不超过 5 秒。
- 场景切换不超过 3 秒。
- 连续游玩 2 小时不出现明显内存增长。
- 战斗 UI 不因对象池复用出现残留状态。
- 存档读取失败时能回退到最近自动存档。

## 10.4 内容完成定义

一项内容只有同时满足以下条件才算完成：

- 设计文档已确认。
- 数据和美术资源已接入。
- 从正常流程可以到达。
- 存档、读档后状态正确。
- 有明确验收人员。
- 没有阻塞性 Bug。
- 平衡数据进入总表。
- 文本进入本地化管线。

# 十二、主要风险与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| 内容量失控 | 版本长期无法上线 | 8 章封顶，支线 20 个封顶 |
| 战斗系统过重 | 开发慢、玩家学习成本高 | 先锁定破防、五行、行动顺序三件事 |
| 剧本反复重写 | 美术和数据返工 | 每章剧情先做流程图，再写正文 |
| 工具不足 | 策划无法独立生产内容 | 优先开发条件编辑器、战斗模拟器、文本管线 |
| 美术成本上升 | 预算超支 | 模块化地图、敌人变体和立绘优先 |
| 存档兼容 | 测试和发售受阻 | 从第一版起带版本号和迁移 |
| 自动化战争 | 战斗退化成看数值 | Boss 特殊机制、阵型和状态必须参与 |
| 伪选择过多 | 玩家不信任剧情 | 关键选择必须有可验证后果 |
| 后期结局推翻前期 | 大量返工 | 第三章前冻结主线和结局条件 |

# 十三、第一周执行清单

如果现在开始，第一周只做以下事情：

1. 确认产品范围为 6–8 小时、8 章、4 人队伍、单机 PC。
2. 确认使用 Ink、Tilemap、数据驱动战斗和 JSON 存档。
3. 完成一页战斗设计：行动顺序、破防、五行、状态。
4. 完成主角和混世魔王的美术草图。
5. 完成第一章流程草图：场景 4 个、战斗 6 场、选择 3 个、Boss 1 个。
6. 建立任务看板和 12 周原型排期。
7. 只制作一场可玩的 5 回合战斗，不制作完整第一章。
8. 在战斗完成后做第一次 5 人试玩，确认“意图、破防、换位”是否可理解。

# 十四、最终完成标准

游戏达到可发售状态时，必须同时满足：

- 玩家可以在正常难度下 6–8 小时通关。
- 八章剧情完整闭环，不依赖外部文档才能理解。
- 四名队员都能加入、成长、参与最终战。
- 至少 4 个结局可正常触发。
- 80 件装备、60 个技能和 9 类经文均可获得。
- 没有无法获得、无效或互相覆盖的内容。
- 主线、支线、存档、地图、战斗和 UI 完成全程回归。
- 新玩家在 15 分钟内理解战斗，在 30 分钟内理解成长。
- 存档兼容稳定版本，崩溃后不会毁掉全部进度。
- 开发团队能明确说出首发没做什么，以及为什么不做。
